## 1. 목표 (Objective)

## 2. 구체적인 구현 내용 (Detailed Implementation Scope)
1. **Provider API 권한 확인**: Verify connected DigitalOcean credential in `cloud_connections` has `access_level = 'READ_WRITE'` and valid OAuth/PAT `droplet:create` scope.
2. **연결된 계정 소유권 검증**: Enforce JWT `user_id` membership in `organization_id` via middleware and PostgreSQL RLS (`SET LOCAL app.current_org_id`).
3. **지원 리전 조회**: Query DigitalOcean `GET /v2/regions` (filtered to `available: true`) and map to `provider_regions`.
4. **지원 플랜 조회**: Query `GET /v2/sizes` and verify requested `sku_id` (`s-2vcpu-4gb`, etc.) is available in the selected region.
5. **서버 이미지 목록 조회**: Query `GET /v2/images?type=distribution` (`ubuntu-24-04-x64`, `debian-12-x64`, etc.).
6. **사양 선택 검증**: Validate CPU, RAM, NVMe/SSD disk, and transfer bundle against `product_specs`.
7. **예상 비용 계산**: Compute itemized hourly rate, 672h/730h monthly cap, IPv4 inclusion, and optional backup (+20%) cost via `EstimationService`.
8. **서버 이름 입력 검증**: Validate RFC-1123 hostname (`^[a-zA-Z0-9][a-zA-Z0-9.-]{1,61}[a-zA-Z0-9]$`).
9. **SSH Key 선택**: Validate user's registered SSH key IDs/fingerprints on DigitalOcean (`GET /v2/account/keys`).
10. **추가 디스크·백업 옵션 설정**: Configure `backups: true/false`, `ipv6: true`, and optional block storage volume attachments.
11. **사용자 비용 승인 검증**: Require a valid, non-expired (<5m), unconsumed `operation_approvals` UUID signed with Step-Up MFA (`X-Step-Up-MFA-Token`).
12. **서버 생성 요청 잠금**: Lock `(organization_id, idempotency_key)` in `resource_operations` with status `APPROVED_QUEUED`.
13. **서버 생성 Job 기록**: Enqueue `cloud:provision:digitalocean` task in `background_jobs` and emit outbox event.
14. **Provider Resource ID 저장**: Dispatch `POST https://api.digitalocean.com/v2/droplets` with tag `cloudscanr-op-id:{op_id}`; immediately persist returned `droplet.id` into `external_resource_id`.
15. **실제 생성 상태 Polling**: Poll `GET /v2/droplets/{id}` with exponential backoff (3s, 5s, 8s, 13s) until `status == "active"` and public IPv4/IPv6 addresses are assigned.
16. **타임아웃 후 상태 재확인 (Timeout Reconciliation)**: If `POST /v2/droplets` times out or drops connection, transition to `TIMEOUT_RECONCILING` and query `GET /v2/droplets?tag_name=cloudscanr-op-id:{op_id}` BEFORE any retry.
17. **중복 생성 방지**: If reconciliation finds the Droplet already exists, adopt its `droplet.id` and continue polling; never issue a duplicate `POST`.
18. **실패 결과 기록**: On 401/402/422/500 errors, transition `resource_operations` to `FAILED_SAFE` with structured `error_code` and `error_message`.
19. **사용자에게 서버 생성 결과 표시**: Update `cloud_resources` (`power_status = 'RUNNING'`) and push SSE notification to `/dashboard/servers/{id}`.
20. **감사 로그 저장**: Append SHA-256 hash-chained record (`prev_hash` -> `entry_hash`) to `audit_logs` with redacted credentials.
