# CLOUD_PROVISIONING_E2E.md — 22 Mandatory Server Provisioning & Management Safety Tests (Article 24)
**Document ID:** `CS-TST-004`

## 1. Complete 22-Scenario Safety Test Specification
| Test ID | Article 24 Mandatory Scenario | Precondition / Fault Injected | Expected Safe System Behavior | Work Orders |
| :--- | :--- | :--- | :--- | :--- |
| `SAF-01` | **1. 정상 서버 생성 (Normal Server Creation)** | Valid READ_WRITE token + valid Cost Approval + Idempotency-Key | HTTP 202 -> Worker creates server with tag cloudscanr-op-id -> Polls to RUNNING -> Audit log saved | `WO-CS-0601, WO-CS-0881` |
| `SAF-02` | **2. 잘못된 API Key (Invalid API Key)** | User submits malformed or invalid provider API key | Preflight check returns HTTP 422 INVALID_PROVIDER_CREDENTIALS; zero job queued | `WO-CS-0556, WO-CS-0882` |
| `SAF-03` | **3. 만료된 API Token (Expired API Token)** | Connected token expires prior to server provisioning execution | Preflight detects 401 Expired -> Marks connection EXPIRED -> Fails safely before provisioning | `WO-CS-0558, WO-CS-0883` |
| `SAF-04` | **4. 읽기 전용 토큰으로 서버 생성 (Read-Only Token Provisioning Attempt)** | Connection has access_level = READ_ONLY or read-only provider token scope | Blocked at API gate and preflight with HTTP 403 READ_ONLY_CONNECTION; KMS write path never invoked | `WO-CS-0562, WO-CS-0884` |
| `SAF-05` | **5. 지원되지 않는 리전 (Unsupported / Unavailable Region)** | User requests SKU in a region disabled or out-of-stock for their account | Preflight region check rejects with HTTP 422 REGION_UNAVAILABLE_FOR_ACCOUNT | `WO-CS-0604, WO-CS-0885` |
| `SAF-06` | **6. 지원되지 않는 플랜 (Unsupported / Deprecated Plan)** | User requests a deprecated or region-incompatible SKU plan | Rejected at validation gate with HTTP 422 PLAN_NOT_SUPPORTED_IN_REGION | `WO-CS-0605, WO-CS-0886` |
| `SAF-07` | **7. 잔액 부족 (Insufficient Provider Account Balance)** | Provider API returns 402/422 Insufficient Funds / Billing Method Required | Transition operation to FAILED_SAFE (PROVIDER_INSUFFICIENT_FUNDS) with clear user message; zero retry loop | `WO-CS-0612, WO-CS-0887` |
| `SAF-08` | **8. 한도 초과 (Provider Droplet/vCPU/GPU Quota Exceeded)** | Provider API returns 422 Account Instance Limit Reached | Transition operation to FAILED_SAFE (PROVIDER_QUOTA_EXCEEDED); zero retry loop | `WO-CS-0613, WO-CS-0888` |
| `SAF-09` | **9. 공급업체 API 장애 (Provider API 500/503 Outage)** | Provider returns HTTP 503 during preflight or status polling | Circuit breaker records failure; safe backoff polling; never blind-retries POST /servers without reconciliation | `WO-CS-0614, WO-CS-0889` |
| `SAF-10` | **10. 서버 생성 요청 타임아웃 (Server Creation Request Timeout)** | HTTP client times out 30s after sending POST /servers | Transition to TIMEOUT_RECONCILING -> Query provider by tag cloudscanr-op-id -> Adopt if created, never double-create | `WO-CS-0615, WO-CS-0890` |
| `SAF-11` | **11. 서버 생성 후 응답 유실 (Lost HTTP Response After 201 Created)** | Provider creates VM but TCP connection drops before response reaches CloudScanr | TIMEOUT_RECONCILING discovers VM via tag cloudscanr-op-id -> Links external_resource_id -> Transitions to POLLING_ACTIVE | `WO-CS-0616, WO-CS-0891` |
| `SAF-12` | **12. 중복 요청 (Concurrent Duplicate Provisioning Requests)** | Client sends two identical POST /api/v1/cloud/servers requests with same Idempotency-Key or double-clicks | Database UNIQUE(organization_id, idempotency_key) & single-use approval_id ensure exactly 1 VM is created | `WO-CS-0617, WO-CS-0892` |
| `SAF-13` | **13. 사용자 승인 취소 (User Cancels or Lets Cost Approval Expire)** | User revokes approval or waits >5 minutes before submitting POST /servers | Rejected with HTTP 403 APPROVAL_EXPIRED_OR_REVOKED; zero provider API call made | `WO-CS-0618, WO-CS-0893` |
| `SAF-14` | **14. 서버 삭제 요청 (Destructive Server Deletion Gate)** | User requests DELETE /api/v1/cloud/servers/{id} | Requires exact hostname match + Step-Up MFA + DELETE_SERVER approval_id; logs before/after state | `WO-CS-0640, WO-CS-0894` |
| `SAF-15` | **15. 다른 사용자 서버 접근 (Cross-Tenant IDOR Access Attempt)** | User in Org A attempts to view, reboot, or delete Org B's server | Blocked by Middleware + PostgreSQL RLS + KMS AAD; returns 404 Not Found and logs SECURITY_ALERT | `WO-CS-0560, WO-CS-0895` |
| `SAF-16` | **16. API Token 철회 (Provider API Token Revoked Externally)** | User revokes API token inside DigitalOcean/Hetzner console | Next sync/action detects 401 Unauthorized -> Marks connection REVOKED -> Prompts user to reconnect | `WO-CS-0588, WO-CS-0896` |
| `SAF-17` | **17. 작업 도중 계정 연결 해제 (Account Disconnected Mid-Operation)** | Admin disconnects BYOC account while a server operation is in POLLING_ACTIVE | Worker gracefully aborts further mutations, wipes KMS DEK/ciphertext, and marks operation ABORTED_DISCONNECTED | `WO-CS-0596, WO-CS-0897` |
| `SAF-18` | **18. 서버 리사이징 비용 변경 (Server Resize Cost Delta Approval)** | User upgrades 2 vCPU ($24/mo) to 8 vCPU ($96/mo) or permanent disk resize | Requires explicit RESIZE_SERVER Cost Approval acknowledging the +$72/mo delta and irreversible disk warning | `WO-CS-0651, WO-CS-0898` |
| `SAF-19` | **19. 백업 실패 (Automated Backup or Snapshot Failure)** | Provider snapshot/backup action fails due to disk lock or quota | Records FAILED_SAFE on operation, alerts user in dashboard/email, preserves server running state | `WO-CS-0665, WO-CS-0899` |
| `SAF-20` | **20. 예산 초과 (Organization Monthly Budget Cap Exceeded)** | Provisioning or resizing would push monthly run-rate above budget_policies.monthly_limit_usd | Hard-blocked prior to approval with HTTP 402 BUDGET_POLICY_EXCEEDED unless Owner signs override | `WO-CS-0682, WO-CS-0900` |
| `SAF-21` | **21. 불일치 리소스 Reconciliation (Drift / Orphan Resource Reconciliation)** | User creates or deletes a server directly in Provider Console outside CloudScanr | Scheduled drift scanner detects mismatch, records resource_reconciliations entry, and updates local state | `WO-CS-0690, WO-CS-0901` |
| `SAF-22` | **22. 감사 로그 검증 (Tamper-Evident Audit Log Verification)** | Every provisioning, power, resize, delete, and security failure is audited | Verifies SHA-256 hash chain (prev_hash -> entry_hash) and DB immutability trigger on audit_logs | `WO-CS-0830, WO-CS-0902` |
